## What's new

### SusFS mount-hiding improvements

- Improved recognition of module bind mounts and overlays by checking their actual backing paths, including mounts with ordinary-looking source names.
- Require all three mount-table hooks before enabling mount hiding. A failed hook now rolls back activation and reports the error instead of leaving partial coverage enabled.
- Match absolute mount rules at directory boundaries, avoiding similarly named neighbouring paths.
- Added backing-helper availability to the mount diagnostics.
- Updated the BZIG and BZID profile checksums and source metadata for the tested shared SusFS payload.

## Validation and current limits

- Native regression checks passed normally and with ASan/UBSan. Android unit tests, driver/daemon matching, APK bundle integrity and release-signature checks passed.
- Device diagnostics on **SM-S948B / BZIG** confirmed all three mount-table hooks were active and seven module-mount records were filtered from the normal Termux reader. Other device variants and firmware profiles still need device testing.
- SusFS LKM remains experimental. Duck Detector's cross-process mount-view warning is not confirmed resolved; the captured root-read views differed only by Android app-data, profile and storage mounts. Installed-app/package-list detections are a separate layer.

## Updating

1. Install **RootMyGalaxyUltra-1.2.6.apk** over the existing app; it uses the same package and release signing key.
2. Perform a **full reboot** to replace the loaded backend and SusFS module. A soft reboot keeps the existing kernel modules loaded.
3. Activate root again through Root My Galaxy Ultra. SusFS loads automatically when enabled in the app.

Use a **UAPI 5-compatible manager** for your selected backend. Updating the manager alone does not replace the loaded driver.
